## 一、项目定位

ContentOps Hub 是面向有声书运营人员的本地优先内容运营综合管理平台。项目围绕番茄畅听多书名运营场景，提供作品导入、身份识别、价值评级、书名简介优化、封面处理、人工审核、多书名测试复盘和结果交付能力。

核心原则：

- 默认使用 Mock 或本地规则，先保证 MVP 可运行。
- OpenAI 文本、图片生成和真实搜索均由用户主动触发。
- 外部服务失败不能导致整个应用崩溃。
- 批量任务允许单条失败，不影响整批。
- 不提交 API Key、本地数据库、上传图片或本地环境文件。

```text
→ 封面评估

→ 人工审核与最终采用
→ 多书名测试结果导入
→ 效果回流与评分校准
→ Excel / ZIP 交付
```

## 五、Excel 导出结构

Excel 保留原始总表 `作品运营建议`，同时新增：

1. `运营总览`
2. `识别与评级详情`
3. `书名简介方案`
4. `封面处理`
5. `测试复盘`
6. `效果回流`

缺失识别、评级、生成、封面评估或复盘结果时，对应字段留空，不会导致导出失败。

## 九、当前限制和风险

1. 阶段 19.2 本地提交尚未推送到 GitHub。
2. 批量任务依赖当前 Node 进程持续运行，服务重启后不会自动恢复。
3. 百度千帆真实搜索可能因频率或额度返回 HTTP 429。
4. 真实搜索 provider 仍需根据正式服务商配额和返回格式持续校准。
5. 图片生成保持单本手动触发，没有批量成本控制后台。
6. 效果回流使用可解释规则，不是统计显著性分析或机器学习模型。
7. 当前不提供登录、权限和多用户隔离。
8. 阶段 20 已修复 PostCSS 和 SheetJS 依赖漏洞，`npm audit` 当前为 0。
