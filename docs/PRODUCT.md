# PRODUCT.md

## 产品定位

`ContentOps Hub` 是本地优先的有声书多书名运营工作台，用于把作品从导入、识别、评级、书名简介生成、封面处理、人工审核、多书名测试回流推进到 Excel / ZIP 交付。

项目品牌称呼当前存在“番茄畅听”和“番茄畅畅听”两种写法，本轮不批量替换，先列为待产品负责人确认事项。

## 目标用户

- 有声书、听书、音频内容运营人员
- 需要批量处理作品资料但不希望直接操作代码或数据库的业务同学
- 需要把作品建议、证据、封面和复盘结论整理成可交付文件的运营团队

## 当前解决的问题

- 批量导入作品资料，并在入库前发现格式、重复和缺失问题。
- 对作品身份、搜索证据和风险进行结构化记录。
- 生成可人工采用或拒绝的 OpenAI 作品价值评级建议。
- 生成书名、简介和封面 Prompt 建议。
- 管理封面上传、远程封面、原图换标题和单本 Image2 重绘结果。
- 保存最终采用书名、简介、封面和审核信息。
- 导入多书名测试结果，形成复盘和效果洞察。
- 导出 Excel 或 ZIP 交付包。

## 第一版已实现范围

- Excel / CSV 作品导入和手动新增作品。
- 作品列表、筛选、分页、勾选、导出和详情页。
- Mock-first 作品识别，支持 configured search 的显式入口。
- OpenAI 作品价值评级运行记录、invalid / failed 留痕、人工采用和补充证据。
- Mock / OpenAI 书名简介生成。
- 封面资产、Mock 封面评估、原图换标题和单本 Image2 重绘。
- 人工审核状态流和最终采用结果。
- 多书名测试结果导入、复盘和效果洞察。
- 批量任务中心 V1：识别、评级、书名简介生成、封面评估和失败重试。
- Excel / ZIP 交付导出。

## 稳定化阶段目标

- 收敛文档事实源，避免 README、交接文档和阶段流水账互相冲突。
- 补齐核心流程验收标准和自动化测试缺口。
- 降低批量任务中断、导出失败、外部 API 误调用和敏感信息泄露风险。
- 在真实业务数据试跑前明确恢复、备份、性能和人工介入边界。

## 明确非目标

- 默认批量调用 OpenAI。
- 默认批量生成图片或执行 Image2 重绘。
- 接入未确认的真实搜索供应商。
- 引入 Redis、BullMQ、复杂 worker 或多租户权限系统，除非后续切片明确批准。
- 自动替代运营人员做最终采用决策。
- 训练机器学习模型或做复杂统计显著性检验。
- 批量替换“番茄畅听 / 番茄畅畅听”品牌称呼。

## 当前暂不确定的产品事项

- 品牌称呼统一为“番茄畅听”还是“番茄畅畅听”。
- 真实搜索供应商、返回字段契约、成本和限流策略。
- 远程封面是否需要缓存并进入 ZIP 交付包。
- 批量任务恢复能力的最小产品表现：自动恢复、标记失败、人工重试或续跑。
- 单本 OpenAI 评级显式成本确认的交互文案和阻断强度。
